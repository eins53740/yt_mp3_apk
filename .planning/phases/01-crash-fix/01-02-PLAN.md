<objective>
Add a "Skip update" button so users can bypass the yt-dlp update step if it hangs on first launch.

Purpose: The `updateYoutubeDL()` call is a blocking network request with no timeout. On slow or unreachable networks, the app stays stuck in UPDATING state indefinitely. Users need an escape hatch to skip the update and use the bundled yt-dlp version immediately.

Output: ViewModel changes (cancellable update job + skipUpdate function) and a UI button visible only during UPDATING state.
</objective>

**Step 3 — Restructure `initialize()` to launch the update as a cancellable child job.**

Replace the current `initialize()` function (lines 81-121) with:

```kotlin
    private fun initialize() {
        viewModelScope.launch(Dispatchers.IO) {
            try {
                updateStatus("Initializing YoutubeDL...")

                // Initialize YoutubeDL
                YoutubeDL.getInstance().init(getApplication())
                Log.d(TAG, "YoutubeDL initialized")

                // Initialize FFmpeg
                updateStatus("Initializing FFmpeg...")
                FFmpeg.getInstance().init(getApplication())
                Log.d(TAG, "FFmpeg initialized")

                // Initialize aria2c for faster downloads
                updateStatus("Initializing Aria2c...")
                try {
                    Aria2c.getInstance().init(getApplication())
                    Log.d(TAG, "Aria2c initialized")
                } catch (e: Exception) {
                    Log.w(TAG, "Aria2c initialization failed (optional): ${e.message}")
                }

                // Launch yt-dlp update as a cancellable child job
                withContext(Dispatchers.Main) {
                    appState = AppState.UPDATING
                    statusMessage = "Updating yt-dlp... (tap Skip to proceed)"
                }
                updateJob = viewModelScope.launch(Dispatchers.IO) {
                    updateYtDlp()
                }
                updateJob?.join()  // Wait for completion, but job can be cancelled by skipUpdate()

                // Transition to READY only if skipUpdate() hasn't already done it
                withContext(Dispatchers.Main) {
                    if (appState == AppState.UPDATING) {
                        appState = AppState.READY
                        statusMessage = "Ready to download"
                    }
                }

            } catch (e: CancellationException) {
                // Normal — skipUpdate() cancelled the parent or child job
                // State already set to READY by skipUpdate()
                throw e
            } catch (e: Exception) {
                Log.e(TAG, "Initialization failed", e)
                withContext(Dispatchers.Main) {
                    appState = AppState.ERROR
                    statusMessage = "Initialization failed: ${e.message}"
                }
            }
        }
    }
```

Key changes from original:
1. Before calling `updateYtDlp()`, explicitly sets `appState = AppState.UPDATING` with "(tap Skip to proceed)" hint in status message
2. Launches `updateYtDlp()` as a separate child coroutine stored in `updateJob`
3. Uses `updateJob?.join()` to wait for it (cancellable wait)
4. After join, checks `appState == AppState.UPDATING` before setting READY — if `skipUpdate()` already set READY, this is a no-op
5. Catches `CancellationException` separately and re-throws (mandatory for structured concurrency)

**Step 4 — Remove the `withContext(Dispatchers.Main)` block inside `updateYtDlp()` that sets appState to UPDATING.**

In the `updateYtDlp()` function (lines 123-153), remove these lines:

```kotlin
                statusMessage = "Updating yt-dlp..."
            }
```

The UPDATING state is now set by `initialize()` before launching the update job. The `updateYtDlp()` function should NOT set appState — it is now a pure worker that just does the HTTP call and logs results. Replace those removed lines with nothing (the function should go straight to the `val updateResult = ...` line).

**Step 5 — Add `skipUpdate()` public function.**

Add after the `retryInitialization()` function:

```kotlin
    /**
     * Called from UI when user taps "Skip update" during UPDATING state.
     * Cancels the yt-dlp update download and transitions to READY immediately.
     * The blocking HTTP call may continue briefly in the background, but the
     * UI becomes responsive immediately. Safe to call from main thread (onClick context).
     */
    fun skipUpdate() {
        updateJob?.cancel()
        updateJob = null
        appState = AppState.READY
        statusMessage = "Ready to download (update skipped)"
    }
```
