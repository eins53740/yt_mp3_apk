**Root build.gradle.kts** — Remove kotlin-android plugin, add new plugin declarations:

Note: `jetbrains.kotlin.android` is REMOVED — AGP 9.0 has built-in Kotlin support and no longer requires the standalone Kotlin Android plugin. Keeping it causes a build error: "The 'org.jetbrains.kotlin.android' plugin is no longer required".

**app/build.gradle.kts** — Four changes:

1. **Update plugins** — Remove kotlin-android, add three new plugins:

Current:
```kotlin
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.jetbrains.kotlin.android)
}
```

Replace with:
```kotlin
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.compose.compiler)
    alias(libs.plugins.hilt.android)
    alias(libs.plugins.ksp)
}
```

Note: `jetbrains.kotlin.android` is REMOVED. AGP 9.0 handles Kotlin compilation via built-in support.

2. **Remove kotlinOptions block** — Delete the entire `kotlinOptions { ... }` block:
```kotlin
// DELETE THIS:
kotlinOptions {
    jvmTarget = "17"
}
```

With AGP 9.0 built-in Kotlin, jvmTarget defaults to `compileOptions.targetCompatibility` which is already `JavaVersion.VERSION_17`. Do NOT add a `kotlin { compilerOptions { } }` block — the defaults are correct.

3. **Remove composeOptions block** — Delete the entire `composeOptions { ... }` block:
```kotlin
// DELETE THIS:
composeOptions {
    kotlinCompilerExtensionVersion = "1.5.1"
}
```

This block is REPLACED by the `compose-compiler` plugin. Leaving it in causes a build warning/error with Kotlin 2.x. Do NOT add a `composeCompiler {}` block in its place — the defaults are correct.

4. **Update dependencies** — In the `dependencies {}` block:
- REMOVE: `implementation(libs.coil.compose)` (Coil is unused — no AsyncImage calls exist in source)
- REMOVE: `// Coil for image loading` comment above it
- ADD: `implementation(libs.hilt.android)`
- ADD: `ksp(libs.hilt.android.compiler)` (use `ksp()` NOT `kapt()` — kapt is deprecated, KSP is the standard with Hilt 2.59+)
- ADD: `implementation(libs.hilt.navigation.compose)`
- ADD: `implementation(libs.lifecycle.runtime.compose)`

Keep ALL existing dependencies unchanged (core-ktx, lifecycle-runtime-ktx, lifecycle-viewmodel-compose, activity-compose, compose-bom, ui, material3, youtubedl, test dependencies).

**DO NOT:**
- Add `kapt` plugin — it is deprecated in favor of KSP with AGP 9.0
- Change `compileSdk`, `targetSdk`, `minSdk`, `versionCode`, or `versionName`
- Change the `splits` block (ABI splits are still supported in AGP 9.0)
- Change the `buildTypes`, `compileOptions`, or `packaging` blocks
- Add a `composeCompiler {}` configuration block — defaults are correct
- Add a `kotlin { compilerOptions { } }` block — defaults from compileOptions are correct

  <name>Task 3: Add Hilt and data class ProGuard rules for release builds</name>
  <files>app/proguard-rules.pro</files>
  <action>
Add Hilt-specific ProGuard keep rules to `app/proguard-rules.pro`. Append AFTER the existing rules (do NOT modify any existing rules).

Add at the end of the file:
```proguard
# Hilt DI — prevent R8 from stripping @HiltViewModel constructors (known AGP 8.9+ bug)
# See: https://github.com/google/dagger/issues/4739
-keepnames @dagger.hilt.android.lifecycle.HiltViewModel class * extends androidx.lifecycle.ViewModel
-keep class dagger.hilt.** { *; }
-keep class javax.inject.** { *; }
-keep class * extends dagger.hilt.android.internal.managers.ViewComponentManager$FragmentContextWrapper { *; }

# Keep DownloaderUiState data class (created in Plan 03)
-keepclassmembers class com.example.yt2local.DownloaderUiState { *; }
```

**Why:** A known bug in Hilt causes R8 to strip `@HiltViewModel`-annotated constructor parameters in release builds. Without this rule, the release APK crashes on first screen load with `NoSuchMethodException`. This affects debug=false builds only — the rule is harmless in debug builds.

The `DownloaderUiState` rule is added proactively for Plan 03 (StateFlow migration) which will create this data class. Per CLAUDE.md: "Add new data classes to ProGuard rules when creating them."

**DO NOT** modify or remove any existing rules in the file.
